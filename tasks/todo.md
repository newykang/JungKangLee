# JungKangLee 작업 체크리스트

[150분 개발 계획](plan.md) · [Vercel 및 QA 실행표](vercel-qa.md)

## 0–35분 · 기본 경로

- [ ] **A** 역할 담당자와 파일 계약을 합의하고 Vercel Git 연결, `main` 추적, 팀원 및 평가자 접근을 확인한다.
- [ ] **A** `feat/demo-base`에서 기본 버튼·카드, 합의한 파일과 데이터 한 건을 연결한다. 데이터는 C가 확인한 첫 기록을 사용한다. 동료 검토 후 병합하고 Vercel Production에서 카드와 출처를 확인한다.
- [ ] **B** 카드, 출처 링크, 모바일 배치 및 로딩·빈 화면·실패 상태를 준비한다.
- [ ] **C** 공식 출처 후보를 모으고 앱 이름, 패키지명, 버전, 날짜와 요약을 대조한다.

## 35–110분 · 병렬 구현과 통합

- [ ] **A · `feat/app-shell`** 앱 선택으로 피드가 바뀌고 같은 브라우저 새로고침 후 선택이 복원된다. 전부 해제하면 전체 피드가 돌아온다. 로컬과 Preview에서 확인한다.
- [ ] **B · `feat/feed-ui`** 휴대폰 화면에서 가로 스크롤 없이 카드를 읽고 공식 출처를 열 수 있다. 키보드로 앱 선택과 출처 링크를 조작할 수 있다. 렌더링 상태와 날짜 표기를 Preview에서 확인한다.
- [ ] **C · `feat/demo-data`** 앱 3개, 릴리스 4건 이상을 채운다. 최소 한 앱에 두 버전 이력을 포함한다. 고유 ID와 패키지 참조를 점검하고, 각 링크와 요약을 공식 원문에 대조한다.
- [ ] **A/B/C** PR에 변경 파일, 테스트 방법·결과, Preview URL 및 SHA를 남긴다. 리뷰는 A→B의 PR, B→C의 PR, C→A의 PR을 기본으로 한다. A가 준비된 PR을 하나씩 병합한다.
- [ ] **A** 110분 시점에 배포 가능한 `main` SHA와 Vercel URL을 고정한다. 미완료 선택 기능이 시연을 막으면 기본 피드와 출처가 동작하는 배포를 확보하고, 미통과 항목은 QA 결과에 기록한다.

## 110–150분 · 평가와 시연

- [ ] **A** Vercel에서 최종 배포 상태와 SHA를 확인한다. 실제 평가자와 같은 조건에서 URL을 연다.
- [ ] **B** 모바일·데스크톱에서 앱 선택, 새로고침, 전체 보기, 출처 링크 경로를 재현한다.
- [ ] **C** `tasks/qa-results.md`에 대상 URL, SHA, 확인 시각, 항목별 결과와 결함을 남긴다. 결과 공유는 이 파일을 기준으로 하며, 앱 배포 이후 결과 문서 전용 커밋이 생겨도 실제 QA한 배포 SHA를 유지한다.
- [ ] **A/B/C** 시연 URL을 열고 전체 피드 → 관심 앱 선택 → 새로고침 → 공식 출처 → 전체 보기 순서로 한 번 리허설한다.
